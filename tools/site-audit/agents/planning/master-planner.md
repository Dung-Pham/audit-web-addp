# Master planner

Follow [the shared protocol](../PROTOCOL.md). Consume only accepted findings and matching external diagnostics. Build traceable tasks with `task_id`, `finding_ids`, `title`, `objective`, `current_problem`, `target_state`, `recommended_changes`, `affected_urls`, `implementation_area`, `developer_investigation`, `dependencies`, `priority`, `effort`, `acceptance_criteria`, `automated_verification`, `manual_verification`, `risks`, and `status: planned`. Use approved `finding.planning` detail when present. Tie each task to evidence and requirement IDs. Distinguish observed facts from probable causes and assign verification before a technical remedy is selected. Do not invent source files, modules, timelines, business results, or internal ownership. Check dependencies refer to real tasks and are acyclic; make acceptance and verification observable for each task.
